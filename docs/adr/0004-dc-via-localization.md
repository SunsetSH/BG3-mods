# 0004. DC через генерацию локализации

Дата: 2026-11-23. Статус: принято.

## Контекст

Нужно показать DC в варианте ответа без Script Extender (ADR 0001). Исследование на игре с Patch 8 Hotfix 10 (последний `Patch8_HotFix10.pak` в `Data`):
- Вариант ответа рисует `Public/Game/GUI/Library/DialogueTemplates.xaml` (`Game.pak`). Текст собирается из `CtxAnswer`, а «[УБЕЖДЕНИЕ]» это параметр с `Type=Tag`, у которого есть только название навыка и подсказка с бонусом. Числа DC во ViewModel варианта нет, поэтому XAML-оверрайд его не покажет.
- Узел `ActiveRoll` в диалоге хранит `DifficultyClassID` (UUID из `DifficultyClasses.lsx`) и хэндлы текста варианта. Ни один из 3727 хэндлов с DC не используется в узлах без проверки.

## Решение

Генератор `scripts/dc_check_generate.py` берёт текст каждого варианта с проверкой из локализации игры, ставит в начало `(DC 15) ` или `(КС 15) ` и пишет файлы `Mods/<папка мода>/Localization/<Язык>/*.loca.xml` с теми же именами, что у игры, включая гендерные `Gender/Female/...`. Термин взят из игры: хэндл `hd45a9fec...`, «DC [1]» / «КС [1]».

## Альтернативы

- XAML-оверрайд `DialogueTemplates.xaml`: DC недоступен в привязках; к тому же файл правят ImpUI и другие UI-моды.
- Script Extender: исключён ADR 0001.

## Последствия

- Работает в любом UI-моде, который показывает текст варианта; ImpUI не мешает.
- Конфликт с модами-переводами (у пользователя Fixed Russian translation): побеждает мод, загруженный позже. Обход: `dc_check_generate.py --base-pak <перевод>.pak` для личной сборки и DC Check ниже в порядке загрузки.
- DC попадает и в историю диалога, так как это тот же текст.
- После патча игры, меняющего диалоги или тексты, нужно перегенерировать и выпустить новую версию.
- Сгенерированные файлы содержат текст Larian и не коммитятся (`.gitignore`), собираются локально.
- Других языков нет: их локализация не меняется, вариант выглядит как в оригинале.
