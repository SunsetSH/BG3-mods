## DC Check (`dc_check`)

### Исследование: как показать DC

- [x] Распаковать `Gustav.pak`/`Shared.pak`, найти, как узел диалога ссылается на проверку и `DifficultyClasses` (UUID → число). Результат в NOTES мода
- [x] Найти XAML виджета диалога (`Game.pak`, Public/Game/GUI) и выяснить, отдаёт ли ViewModel варианта ответа DC: не отдаёт
- [x] Выяснить, как в текст варианта попадает «[Убеждение]»: это параметр `Tag` в UI, не строка локализации
- [x] Выбрать механизм: генерация локализации, ADR 0004

### Реализация

- [x] Генератор `scripts/dc_check_generate.py`: таблица DC, узлы `ActiveRoll`, тексты en и ru с гендерными вариантами
- [x] Учёт DC, зависящего от акта: UUID в узле уже указывает на строку акта (`Act2_Medium`), таблица собирается из трёх файлов
- [x] Проверки без DC (атаки, нулевой UUID) не помечаются; текст с разными DC получает `(DC 5/10)`
- [x] Преимущество и помеха: не показываем. Игра пишет их на экране броска, а значение `Advantage=1` в данных не всегда совпадает с `AdvantageReason`, проверить без игры нельзя
- [x] Совместимость с модами-переводами: `dc_check_generate.py --base-pak`
- [x] Ручной прогон по `mods/dc_check/TESTING.md` (пользователь, 2026-11-24: работает, доработки не нужны)

### Выпуск

- [x] `scripts/pack.py dc_check` собирает `paks/DCCheck.pak` и `build/DCCheck-<версия>.zip` для загрузки
- [x] Подготовить DC Check 1.0.0 к общему релизу на GitHub
- [ ] После каждого патча игры: `dc_check_generate.py --refresh`, `pack.py dc_check`, новая версия
